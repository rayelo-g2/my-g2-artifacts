Repository audit

Reading UE through its Git history

This report turns commit history into a first-pass map of files to read, risks to validate, and team signals to keep in mind before changing product-facing code.

Executive Summary

Methodology: combine recent app-code churn, fix-oriented commit history, contributor concentration, monthly commit rhythm, and rollback-style commit messages. Each signal is noisy on its own. The useful output is the overlap.

The strongest technical reading target is the product, category, and review path. app/models/product.rb is the clearest file-level signal because it leads the recent churn list and the fix-oriented history list. app/controllers/products_controller.rb, app/models/survey_response.rb, and app/controllers/categories_controller.rb are close behind.

The team-history signals are less alarming. Authorship is broadly distributed by commit count, recent commit volume is up, and the rollback signal is measurable but not dominant relative to total volume.

Highest Risk

Product, category, review. These files appear repeatedly across churn and fix-oriented history.

Ownership

Ownership is sanely distributed. The top all-time author accounts for 19.4% of non-merge commits.

Momentum

Recent activity is up. The average rose from 332 to 491 commits per month across the compared windows.

Rollback Signal

61 matches in one year. Almost all are revert messages, about 1.0% of the one-year commit volume.

Recommended Reading Order

Methodology: start with files that overlap between the one-year churn command and the fix-oriented command. That points to code that changes frequently and has been repeatedly touched by repair work.

Firefighting Signal

Methodology: run git log --oneline --since="1 year ago" | grep -iE 'revert|hotfix|emergency|rollback'. This finds rollback-style language and incident vocabulary in recent commits.

One-Year Commits

5,912 commits in the same recent window.

Matched Commits

61 matches for revert, hotfix, emergency, or rollback.

Adjusted Count

60 matches after excluding auto revert phrasing.

Incident Terms

0 explicit hotfix, emergency, or rollback matches.

Interpretation: the signal is revert-heavy rather than hotfix-heavy. It is enough to justify checking deploy safety and test confidence around affected areas, but it is not catastrophic relative to total commit volume.

Commands And Scope

Methodology: the command set is intentionally simple and reproducible. App-specific file queries run from /ue/app. Repository-wide team and rhythm queries run from /ue.

cd /ue/app
git log --format=format: --name-only --since="1 year ago" -- . | grep -v '^$' | sort | uniq -c | sort -nr | head -20

cd /ue
git shortlog -sn HEAD --no-merges
git shortlog -sn HEAD --no-merges --since="6 months ago"

cd /ue/app
git log -i -E --grep="fix|bug|broken" --name-only --format='' -- . | grep -v '^$' | sort | uniq -c | sort -nr | head -20

cd /ue
git log --format='%ad' --date=format:'%Y-%m' | sort | uniq -c
git log --oneline --since="1 year ago" | grep -iE 'revert|hotfix|emergency|rollback'

The churn query is limited to files under /ue/app and the last year. The fix-oriented query is limited to files under /ue/app across all available history, so a file can have a higher fix-oriented count than recent churn count.
