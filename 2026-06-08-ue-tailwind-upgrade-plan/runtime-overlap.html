Tailwind upgrade finding

Main UE and Elevate Tailwind can load together

Answer to the scoping question: the two current Tailwind-generated CSS bundles are not fully isolated by route. Shared web-style layouts can load both nessy_app.css and Elevate's application.css.

Bottom line: Elevate utilities are class-prefixed with elv-, which limits direct utility-name collisions, but Elevate CSS is still loaded alongside the main Tailwind output on shared routes. Treat bundle order, Tailwind base/preflight, and non-utility selectors as shared-page risks.

Evidence

Signal Finding Why it matters
Current route HTML curl -k against https://my.g2.test/g2-seller-solutions/home redirected locally to the login surface and emitted both https://www.g2.test/assets/nessy_app.css and /elevate-assets/application.css. This proves at least one unauthenticated web-style page loads both Tailwind outputs at runtime. Authenticated seller-home checks should use the in-app browser session.
Main CSS entrypoint webpack/assets/stylesheets/nessy_app.scss imports tailwindcss/base, tailwindcss/components, and tailwindcss/utilities. nessy_app.css contains the main UE Tailwind output from root tailwindcss: ^3.1.8.
Elevate CSS entrypoint engines/elevate/app/assets/stylesheets/elevate/application.css imports tailwindcss/base, tailwindcss/components, and tailwindcss/utilities. Elevate's bundle contains its own Tailwind output from engines/elevate tailwindcss: ^3.4.10.
Shared partial engines/web_style/app/views/web_style/javascript/_header.html.slim calls elevate_asset_tags. Any layout rendering the shared web-style JS header can receive Elevate CSS and JS.
Shared Nessy partial engines/web_style/app/views/web_style/stylesheet/_nessy_styles.html.slim links nessy_app. Many web-style layouts load main UE Tailwind through nessy_app.
Explicit overlap layout engines/widget_library/app/views/layouts/widget_library/application.html.slim links nessy_app, vendor_admin_assets, and elevate_asset_tags. There are routes intentionally designed with both styling systems present.
Elevate prefix The resolved @g2crowd/elevate/tailwind preset reports prefix: "elv-". Most Elevate utilities should not collide directly with unprefixed main Tailwind utilities such as flex, m-1, or bg-white.

Implication For The Upgrade

  • Version unification to Tailwind 3.4.19 is even more valuable because overlapping routes currently combine output from Tailwind ^3.1.8 and ^3.4.10.
  • The v3 unification should compare generated nessy_app.css and Elevate application.css, not just package-lock changes.
  • A later v4 plan should not assume Elevate can be upgraded with zero effect on shared web-style routes unless those routes are proven not to load elevate_asset_tags.
  • Because Elevate utilities are prefixed, the most likely overlap risks are base/preflight, component CSS, imported vendor CSS, CSS variables/tokens, and load order rather than direct utility selector name collisions.
