Product, category, review

The clearest churn-and-bug overlap is in app/models/product.rb, app/controllers/products_controller.rb, app/models/survey_response.rb, app/controllers/categories_controller.rb, and related product/category views.

Firefighting Signal

61 matches in 1 year

The firefighting query matched 61 recent commits, almost entirely revert messages. That is about 1.0% of 5,912 commits in the same one-year window.

Methodology

The conclusions combine three history probes: recent file churn from /ue/app, bug-message hotspots from /ue/app, and repository-wide ownership and delivery signals from /ue. Churn shows where code changes repeatedly, bug-message history shows where fixes tend to cluster, and the overlap points to files worth reading before making related changes.


Read These First

  • app/models/product.rb is the strongest signal: top churn file in the app over the last year and top bug-message hotspot across history.
  • app/controllers/products_controller.rb sits near the top of both lists, making it a likely high-blast-radius controller.
  • app/models/survey_response.rb has very high bug-message history and still appears in the one-year churn list.
  • app/controllers/categories_controller.rb and app/views/categories/overview.html.slim suggest category pages deserve early inspection.
  • app/controllers/vendor_admin/performance_analytics_controller.rb appears in both lists, but the counts are lower than the core product/category files.

Interpretation

  • The highest-risk surfaces are not isolated files; they cluster around product pages, reviews, categories, survey responses, users, and external clickthroughs.
  • The all-time bug query is commit-message dependent. It is useful for triage, but it should be validated against incident history, flaky specs, ownership, and current product plans before prioritizing remediation.
  • Authorship distribution looks healthy by commit count, but squash merges can blur real authorship. Treat this as a first-pass signal, not a staffing conclusion.
  • The revert count is not catastrophic relative to total commit volume, but 60+ revert-like commits in a year is enough to justify looking at deploy safety and test confidence around the affected areas.

Recommended Next Step

For a focused code read, start with app/models/product.rb and trace outward through ProductsController, the product review views, category overview rendering, and survey response behavior. That path follows the strongest overlap rather than the newest local work.

Methodology

The churn list was generated from /ue/app with git log --format=format: --name-only --since="1 year ago" -- . | grep -v '^$' | sort | uniq -c | sort -nr | head -20. The bug-hotspot list used git log -i -E --grep="fix|bug|broken" --name-only --format='' -- . | grep -v '^$' | sort | uniq -c | sort -nr | head -20. Files appearing in both lists are treated as higher-risk reading targets because they change often and are repeatedly touched by fix-oriented commits.

Commands Run

Churn and bug-hotspot commands were run from /ue/app so generated files, lockfiles, and root-level configuration would not dominate the result. The commands use an explicit -- . pathspec to keep output scoped to the current directory. The shortlog commands include HEAD because this local Git invocation returned no rows without an explicit revision.

cd /ue/app
git log --format=format: --name-only --since="1 year ago" -- . | grep -v '^$' | sort | uniq -c | sort -nr | head -20

cd /ue
git shortlog -sn HEAD --no-merges
git shortlog -sn HEAD --no-merges --since="6 months ago"

cd /ue/app
git log -i -E --grep="fix|bug|broken" --name-only --format='' -- . | grep -v '^$' | sort | uniq -c | sort -nr | head -20

cd /ue
git log --format='%ad' --date=format:'%Y-%m' | sort | uniq -c
git log --oneline --since="1 year ago" | grep -iE 'revert|hotfix|emergency|rollback'

Scope Notes

The churn query is limited to files under /ue/app and the last year. The bug-hotspot query is limited to files under /ue/app across all available history. That means a file can have a higher bug-message count than recent churn count.
