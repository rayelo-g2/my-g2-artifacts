Strategic Use Signal

Storybook appears to have been a focused development and documentation aid for NeRF/review-form states rather than a broad design-system catalog.

Intended use

  • NeRF/review-form component development in isolated states.
  • Documentation of edge cases that are hard to reproduce in Rails flows.
  • Actions addon tracing of event-driven review-form interactions.
  • Widget Library iframe access to this Storybook via nerf.html.slim.
  • Utility/atomic CSS documentation.

Evidence

  • .storybook/README.md calls Storybook both a development-time aid and a documentation tool.
  • webpack/assets/javascripts/reviews/components/README.md frames Storybook as the fast way to develop NeRF visual states, edge cases, and factories.
  • engines/widget_library/app/views/widget_library/storybooks/nerf.html.slim points development to http://localhost:3091 and non-development to /storybook/.

Counter-signal

  • The NeRF README still says to run yarn storybook:nerf, but package.json has no storybook:nerf script.
  • Root .storybook/README.md describes making new Storybook module folders under .storybook, but only the root config remains.
  • Static deployment language says "Not yet", while history shows staging/static work existed later and CI was subsequently removed.

Maintenance Signal

The codebase still carries useful stories, but the operational Storybook surface looks neglected.

Positive or neutral

  • Story files still exist and are tied to review-form scenarios.
  • Recent commits touched story-related paths, including c2d5d9cba7 for font updates and 7b9d26b3d7 for a review-form layout experiment.
  • Package scripts and Storybook addon dependencies still exist.

Negative

  • Local dev and static build both fail today.
  • The stack is still on Storybook 6.5.x, a Webpack 4-era setup.
  • Current dependency code ships modern syntax that this Storybook path does not transpile correctly.
  • At least one loaded story has a stale import/export contract.
  • .github/workflows/storybook.yml was removed in 2352e8e460 ci: Remove storybook workflow.
  • ViewComponent Storybook was dropped in 7bddd9773a chore: Drop ViewComponent storybook (#33179).
  • Docs reference removed scripts and old deployment/status assumptions.

Maintenance read: Storybook is still present because historical review-form stories remain useful, but it does not look actively maintained as a reliable local or CI workflow.

Recommendation

No upgrade or cleanup was made as part of this audit. The next decision should be whether this surface still has an owner.

If keeping

Repair Storybook as explicit owned work for review-form state development. Start by moving off the current Webpack 4-era builder path or transpiling modern dependencies, then fix loaded story imports and stale docs.

If not keeping

Deprecate it by default, preserve only still-useful review-form examples, and remove stale Widget Library entry points and docs in a dedicated cleanup issue.

Repair path

  1. Upgrade the Storybook builder path off this Webpack 4-era setup, or explicitly transpile modern dependency packages that now ship ??, optional chaining, and modern ESM.
  2. Fix loaded story imports, starting with webpack/doc/review_form/Categories.stories.mdx.
  3. Decide whether storybook-addon-recoil-flow is needed; remove or wire it.
  4. Update docs to replace yarn storybook:nerf with yarn storybook:dev / yarn storybook:start.
  5. Reintroduce a minimal CI/static build check if Storybook remains supported.
  6. Revisit the Widget Library iframe route so it does not point users to a broken local surface.

Deprecation path

  1. Mark the root Storybook scripts/docs as deprecated.
  2. Preserve or migrate only the review-form scenarios that still carry product value.
  3. Remove stale Widget Library Storybook entry points and obsolete docs in a dedicated cleanup issue.

Practical recommendation: deprecate by default unless a current review-form owner confirms they still want this workflow. If they do, create a focused repair issue before any migration or upgrade work.
