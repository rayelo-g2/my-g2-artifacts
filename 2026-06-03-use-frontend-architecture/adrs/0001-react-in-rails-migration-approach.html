Architecture Decision Record

ADR 0001: React-in-Rails Migration Approach

Adopt React-in-Rails as the default migration approach for relevant G2DM seller surfaces moving into MyG2.

StatusAccepted
Date2026-06-03
ProjectUnified Seller Experience

Context

The Unified Seller Experience will consolidate the current G2DM Vendor Portal / UVP experience into MyG2. Recent POCs evaluated whether the team should move MyG2 capabilities into G2DM, rebuild G2DM screens as Rails views inside MyG2, or reuse existing G2DM React views inside MyG2.

The timeline is a major constraint: the project should complete the main migration work by October, with November as the external deadline and launch-readiness buffer.

Decision

Use MyG2 Rails as the host application and mount migrated G2DM React views inside Rails-rendered MyG2 pages.

  • Rails owns routing, authorization, session handling, data loading, and backend actions.
  • React owns the migrated view rendering and local UI state inside the mounted page surface.
  • Core G2DM React components should be adapted to match Elevate visual style and expected behavior.
  • React Router should not become the primary route owner for migrated MyG2 pages.

Why This Decision

The decision is based on reuse and delivery efficiency. The existing G2DM implementation is already built in React. Reusing those views is faster than rebuilding every screen as Rails views, and it avoids the larger product and platform cost of moving MyG2 into G2DM.

This is not primarily a decision about needing React-specific reactivity on every page. Some pages may still be simple enough to implement directly as Rails views, but the default migration path is to reuse existing React implementation where practical.

Options Considered

Option Pros Cons
Move MyG2 capabilities into G2DM Cleaner frontend/backend separation in the long term. High effort to adapt MyG2-specific permissions, sessions, and feature coverage. Not feasible for the November deadline.
Rebuild G2DM screens as Rails views in MyG2 Keeps implementation native to Rails/MyG2. POC showed slower migration and more iteration; recreates already-working React behavior across many routes.
Mount/migrate G2DM React views into MyG2/Rails Fastest practical path; maximizes reuse; lets the team focus on integration, styling, and data wiring. Requires care to keep component behavior, visual style, routing, and backend integration consistent inside MyG2.

Consequences

Positive

  • Accelerates migration by reusing already-working G2DM React code.
  • Keeps MyG2/Rails responsible for platform concerns and backend integration.
  • Creates a repeatable route migration pattern once the first route is proven.

Tradeoffs

  • The team must maintain alignment between Rails/Elevate components and adapted React components.
  • Actively changing product areas need sequencing rules to avoid repeated rework.
  • Testing must cover both Rails integration behavior and mounted React view behavior.

Follow-Up Decisions

  • Data layer pattern for React views calling Rails endpoints.
  • Component adaptation checklist and ownership model.
  • Route sequencing and feature cutoff rules.
  • Authorization/session integration pattern for migrated routes.
  • Tracking validation requirements for migrated React-in-Rails pages.
